# Data Dictionary — SaaS FinTech Funnel & Conversion Analysis

## Users Table

| Column | Data Type | Description |
|---|---|---|
| `user_id` | Integer | Unique identifier for each user. Primary key. |
| `signup_date` | Date | Date the user signed up for the product. |
| `acquisition_channel` | Text | Channel through which the user was acquired (`organic`, `paid_search`, `social`, `affiliate`, `referral`). |
| `device_type` | Text | Device platform used at signup (`ios`, `android`, `web`). |
| `country` | Text | Country where the user is located. |
| `age` | Integer | User's age in years. |
| `occupation` | Text | User's occupation. |
| `referral_source` | Text | Source of the referral (e.g., Existing Customer, Employee, Partner App, Community Forum). Populated only when `acquisition_channel` = `referral`; `NULL` otherwise. |
| `marketing_campaign_id` | Integer | Marketing campaign associated with the user's acquisition. Foreign key to `marketing_campaigns.campaign_id`. `NULL` for organic and referral users, who have no associated campaign. |

## Funnel Events Table

| Column | Data Type | Description |
|---|---|---|
| `event_id` | Integer | Unique identifier for each funnel event. Primary key. |
| `user_id` | Integer | User associated with the event. Foreign key to `users.user_id`. |
| `event_type` | Text | Funnel stage the event represents, in expected sequence order: `signup`, `email_verified`, `kyc_submitted`, `kyc_approved`, `bank_linked`, `first_deposit`, `plan_selected`, `subscribed`. Standardized during cleaning (lowercased, underscore-separated). |
| `event_timestamp` | Datetime | Timestamp the event occurred, to microsecond precision. |
| `platform` | Text | Platform the event was logged on (`ios`, `android`, `web`). |

## Subscriptions Table

| Column | Data Type | Description |
|---|---|---|
| `subscription_id` | Integer | Unique identifier for each subscription. Primary key. |
| `user_id` | Integer | User associated with the subscription. Foreign key to `users.user_id`. |
| `plan_tier` | Text | Subscription plan tier (`free`, `plus`, `premium`). |
| `mrr` | Decimal | Monthly recurring revenue generated by the subscription. |
| `start_date` | Date | Date the subscription began. |
| `end_date` | Date | Date the subscription ended. `NULL` while the subscription is active. |
| `status` | Text | Current subscription status (`active`, `canceled`, `past_due`). |
| `cancellation_reason` | Text | Reason the subscription was canceled (e.g., `technical_issues`, `too_expensive`, `poor_support`). `NULL` unless `status` = `canceled`. |
| `payment_method` | Text | Payment method on file (`credit_card`, `debit_card`, `ach_transfer`, `paypal`). `NULL` for $0 free-tier subscriptions with no payment method. |

## Marketing Campaigns Table

| Column | Data Type | Description |
|---|---|---|
| `campaign_id` | Integer | Unique identifier for each marketing campaign. Primary key. |
| `campaign_name` | Text | Name of the marketing campaign. |
| `channel` | Text | Acquisition channel the campaign ran on (`paid_search`, `social`, `affiliate`, `organic`). |
| `cost` | Decimal | Total cost of the campaign. |
| `start_date` | Date | Date the campaign began. |
| `end_date` | Date | Date the campaign ended. |

## Derived Fields

The following fields are not part of the source data — they were engineered
during the Python analysis (`notebooks/funnel_analysis.ipynb`) while building
a single user-level `master` dataframe (one row per user) for the cohort,
statistical, and visualization work. They do not exist in the raw or cleaned
CSVs.

| Field | Type | Description |
|---|---|---|
| `sequential_max_stage_rank` | Integer (-1 to 7) | Furthest funnel stage a user reached, counted only as an unbroken prefix from `signup` — a stage only counts if every stage before it was also logged. `-1` if the user has no valid stage. |
| `furthest_stage_reached` | Text | `sequential_max_stage_rank` mapped back to its stage name (e.g., `kyc_submitted`). `NULL` if no stage was reached. |
| `is_subscriber` | Boolean | `True` if the user has a matching record in `subscriptions` (the ground-truth definition of "subscribed" used throughout the analysis, in place of the raw `subscribed` funnel event, which includes 21 phantom events with no matching subscription). |
| `plan_tier`, `mrr`, `status`, `cancellation_reason`, `subscription_start_date` | Text / Decimal / Date | Subscription fields merged onto the user-level `master` dataframe from `subscriptions` (via `user_id`); `NULL` for non-subscribers. `start_date` is renamed to `subscription_start_date` to distinguish it from `users.signup_date`. |
| `days_to_convert` | Decimal | Days between a user's first `signup` event and first `subscribed` event, restricted to actual subscribers (per `is_subscriber`) and to non-negative durations only — excludes ~8 users whose `subscribed` event timestamp precedes their `signup` event timestamp (same pre-signup-timestamp data-quality issue flagged in `schema_and_load.sql`). `NULL` for non-subscribers or excluded users. |
| `signup_month` | Text | `signup_date` truncated to year-month (e.g., `2024-03`), used to group users into signup cohorts. |

## Known Data Quality Issues

| Table | Column | Issue | Resolution |
|---|---|---|---|
| `funnel_events` | `user_id` | Orphaned events referencing a `user_id` not present in `users` | Retained in raw data; excluded from user-level analysis via `LEFT JOIN`/anti-join rather than deleted |
| `funnel_events` | `user_id`, `event_type`, `event_timestamp`, `platform` | Duplicate event logs (identical values across all four fields) | Removed during SQL cleaning using `ROW_NUMBER()`, retaining the lowest `event_id` per duplicate group |
| `funnel_events` | `event_timestamp` | Events with a timestamp earlier than the user's `signup_date` | Flagged and retained for data-quality review; excluded only from time-based analysis |
| `funnel_events` | `event_type` | 21 `subscribed` events with no matching record in `subscriptions` ("phantom" subscriptions) | Retained in the event log; excluded from conversion calculations, which use `subscriptions` as the source of truth for "subscribed" status |
| `funnel_events` | `event_type` | Inconsistent raw casing/spacing (e.g., `KYCApproved`, `Plan Selected`) | Standardized to lowercase, underscore-separated values during cleaning |
| `subscriptions` | `subscription_id` | 3 rows share a duplicate `subscription_id` | Skipped on load via `LOAD DATA ... IGNORE`, which drops rows on primary-key conflict |
| `subscriptions` | `cancellation_reason` | Reason populated on rows where `status` was not `canceled` | Nulled out during cleaning; reason retained only where `status` = `canceled` |
| `users` | `marketing_campaign_id` | References a `campaign_id` not present in `marketing_campaigns` | Validated via anti-join during cleaning; relationship documented but not enforced by a foreign key |

## Notes on Analysis Definitions

- **Conversion / "subscribed" status** is defined by the presence of a matching
  record in the `subscriptions` table, not by the `subscribed` event in
  `funnel_events`. The event log alone would overstate conversion: 1,088 users
  have a `subscribed` event, but only 1,085 have a matching `subscriptions`
  record (the 21 phantom-subscription users, minus overlap, net to this gap) —
  the analysis uses 1,085 as ground truth throughout the SQL, Python, and
  dashboard work.
- **Funnel stage order** follows the sequence listed in `funnel_events.event_type`
  above (`signup` through `subscribed`); this ordering is used throughout the
  SQL, Python, and dashboard work to compute stage-to-stage drop-off. In the
  Python phase, a stage only counts toward a user's furthest-reached stage if
  every prior stage in the sequence was also logged (see `sequential_max_stage_rank`
  in [Derived Fields](#derived-fields)).
